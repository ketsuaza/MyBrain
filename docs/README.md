# 読書メモ

『本を読む本』の点検読書・分析読書を、欄を選んで埋めていく HTML。

分析読書の規則1〜15のラベルは、訳書（講談社学術文庫）の「分析読書の三段階のまとめ」の文言である。章の中の規則の文言は、各欄の説明（？）に引いてある。規則12〜14は反対の根拠、規則15は判断保留の根拠として書く（まとめの注による）。前の版（規則11まで）で保存した読書メモは、「読み込む」と新しい形に直る。

- iPhone など: https://ketsuaza.github.io/MyBrain/ （GitHub Pages。`main` の `docs/` が出る）
- Mac: この `docs/index.html` をブラウザで開く

## ファイル

| ファイル | 役割 |
| --- | --- |
| `index.html` | 入力する画面 |
| `factcheck.js` | Agent のファクトチェックの結果の正本。HTML が読んで、規則9の命題の下に出す |
| `sample.js` | 動作確認用のサンプル。HTML が開くたびに読み、初めて見たサンプルだけを本の一覧に足す |

写しは置かない。ツールの正本はこの `docs/` だけである。

## データの出どころ

| データ | 出どころ | 読むとき |
| --- | --- | --- |
| ブックリスト（書名、等級、評価、読書状況） | リポジトリ直下の `book_principles.json`。GitHub の `main` から読む | HTML を開くたび |
| 著者・出版社・刊行日 | openBD | 「本を足す」で本を選んだとき |

- ブックリストに出るのは、`main` に入った内容である。手元の未マージの変更は出ない。反映は最大5分遅れる。
- 入力の画面は、ブックリストの取得を待たずに出る。取得のあいだ、「本を足す」には「ブックリストを読み込み中」と出て、届くと表に出る。
- 通信できないとき（8秒たっても応答がないときを含む）は、ブックリストが空になる。書誌は欄に直接書ける。

## 保存

正本は vault の `60_notes/読書メモ/{書名}.md`。HTML の「Obsidian に保存」で書き出す。
入力中の状態はブラウザに残る。同じブラウザの2つのタブで開いていても、片方のタブの入力は、もう一方のタブに取り込まれる（同じ欄を両方のタブで書いたときは、あとから書いたほうが残る）。2つのタブで行を取り違えないよう、用語・要点・根拠・区分の行を消した印を、入力とは別に、ブラウザの `dokusho-memo.v2.cuts` に残す（読書メモの `state` には入らない）。Mac と iPhone では別々になるので、受け渡しは、保存した Markdown を「読書メモから読み込む」に貼る。

下読みの「この本にはない」、「分からなかった所」の「なかった」、「やること」の「やらない」は、欄を隠すだけで、書いた内容は消さない。押し直すと、内容が戻る。隠しているあいだ、Markdown の本文には「この本にはない」などとだけ出る（隠れた内容は、末尾の `state` に残る）。
この印は、`state` の `v._alt`（例: `{ "s3": true }`）に、欄の内容とは別に持つ。前の形（欄の値そのものが `"__alt__"`）の読書メモは、「読み込む」と新しい形に直る。ブラウザに残っている前の形の状態も、開いたときに直る。

表面読みの「何がどのように詳しく述べられているか」は、`state` の `v.points` に、組（`{ "what": "何が", "how": "どのように" }`）の一覧で持つ。1つの組が、1つの「何が」と、それに対応する「どのように」である。前の形（`v.points` が文の一覧）の読書メモは、「読み込む」と、文が「何が」に入り、「どのように」が空の組に直る。ブラウザに残っている前の形の状態も、開いたときに直る。

規則4の問題（`state` の `v.qs` の1件。`{ "id": "Q2", "t": "問いの文", "parent": "Q1" }`）は、問いの型を選んだときだけ、任意の `type`（例: `"type": "原因"`）を持つ（型のない、これまでの読書メモは、そのまま開ける）。

## 公開の範囲

このリポジトリは公開である。`factcheck.js` には、読書メモに書いた命題の文が入る。読書メモの本文は入らない。

## テストとデータのガード

道具はリポジトリ直下にある。初めに `npm run setup` を1回行う（Playwright と Chromium を入れ、pre-commit のフックをつなぐ）。
`node_modules` は iCloud に同期されないよう、`node_modules.nosync` へのリンクになっている。

| コマンド | すること |
| --- | --- |
| `npm test` | E2E の仕様（`tests/e2e/`）とガードの仕様（`tests/guard/`）を全部実行する |
| `npm run e2e` | E2E の仕様だけ。主な状態のスクリーンショットを `screenshots/` に撮る |
| `npm run guard` | コミットしようとしている版を HEAD と比べ、件数を出す |

E2E の仕様が扱うこと:

- ブックリストの全件の表示と並べ替え
- 1280x800 でダイアログがスクロールしないこと（一覧の表の縦だけは中でスクロールする）
- 規則1〜15のラベルがまとめの文言と同じこと
- 各規則の欄の働き
- 前の形の読書メモの移行
- 命題どうしを3クリック以内でつなげること
- 「この本にはない」「なかった」「やらない」を押しても内容が残ること
- 保存した Markdown が有効なこと
- サンプルの命題にファクトチェックの結果が出ること
- 390px の幅で横にはみ出さないこと
- 文字を入力したら、その内容を使うほかの欄も、その場で最新になること
- ボタンやプルダウンを操作しても、フォーカスが失われないこと
- すべての入力欄に、読み上げられる名前があること（選んで切り替えるボタンと「？」は、いまの状態も伝える）
- 読み込んだ読書メモの id や判定に HTML が書かれていても、文字として出るだけで、スクリプトが動かないこと
- 自由メモにコードブロックがあっても、保存した読書メモを読み込めること
- 文を消した命題・部分・問題への参照を、未選択として扱うこと
- 「読み込む」に貼った本と同じ本がブラウザにあり、中身が違うときだけ、置き換える前に確認が出ること
- 同じブラウザの2つのタブで開いていても、片方の入力がもう一方の入力を消さないこと（番号のない一覧を、でたらめな順で操作したときを含む）
- 中身のある命題・部分・問題の「×」を押すと、消す前に確認が出ること
- ブックリストの取得を待たずに、入力の画面が出ること
- 命題の文、部分の概要、根拠、問題の文が、長くても、入力欄の中で折り返して全部見えること
- 幅の狭い画面（620px 以下）では、固定の見出しが本の選択の行だけになること
- 文字の欄の Enter が、同じ行の次の欄へ進み、一覧の最後の行の最後の欄でだけ、同じ並びの行を足すこと
- 390px の幅で、「本を足す」の表が横にスクロールしなくても読め、小さなボタン（「？」「×」「↑」「↓」）の押せる範囲が縦横 32px 以上あること
- これまで仕様のなかった、もとからの働き（再読み込みのあとも入力が残ること、サンプルの足され方、通信の失敗、`file://` で開くこと、読了、本を消すこと、「Markdown をコピー」など）
- 表面読みの「何がどのように詳しく述べられているか」を、「何が」と「どのように」の組で書けること（前の形の読書メモが組に直ることを含む）
- 行を足すボタンのラベルが、何をどこに足すかを表す名詞になっていること
- 本の種類による注意（「実践書では…」「文学には…」）が、欄の上に出ないこと
- 下読みの「何についての本か」の欄から離れたときに、その答えが規則2の欄へ写ること
- キーボードで「↑」「↓」「×」を押したあと、フォーカスのある部品が固定の見出しの下や画面の外に出たら、見える所まで画面が動くこと
- 規則4の欄が、主な問いと、その下の従属する問いに分かれ、問いの型を任意で選べること

pre-commit のフック（`.githooks/pre-commit` → `scripts/guard-data.js`）は、`book_principles.json`、`factcheck.js`、`sample.js` が消えたり空になったり、件数（本、命題、サンプル）が HEAD から10%を超えて減ったりすると、コミットを止める。意図して減らすときは `git commit --no-verify` で通す。

## Agent の作業

手順は、スキル `reading-memo`（`~/.skillport/skills/reading-memo`）にある。

- 命題のファクトチェック: 「読書メモ『書名』の命題をファクトチェックして」
- 用語集への追加: 「読書メモ『書名』の用語を用語集に入れて」

`factcheck.js` は、スキルの `scripts/write_factcheck.py` で書く。手で書き換えない。
